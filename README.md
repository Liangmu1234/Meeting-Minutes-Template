# Meeting-Minutes-Template

售前测试分析会议纪要模板库。仓库按产品线提供可直接填写的 Excel 会议纪要模板，并提供一个通用的项目资料归档目录，帮助项目团队统一记录测试背景、参与角色、会议结论、遗留问题和测试过程资料。

## 适用场景

- 售前测试、方案验证、招标测试、入围测试等项目的启动或分析会议。
- 需要市场、SE、研发、服务、代表处或总部工程师等多角色共同参与的项目。
- 需要按统一格式沉淀会议纪要、测试资料、日报和复盘报告的项目。

根目录目前提供 26 份产品线模板，覆盖 AD、AIGC、CAS&UIS、CloudOS、iMC&准入、SD-WAN、SeerFabric、U-center、云安全、无线、存储、备份、大数据、服务器、智算中心、路由交换、防火墙与应用交付、零信任等方向。具体模板以文件名为准。

## 快速开始

1. 从根目录选择与项目所属产品线最匹配的 `.xlsx` 模板。
2. 复制模板到项目工作目录，并按项目名称或项目编号重命名；请保留根目录中的原始模板不被直接修改。
3. 复制 `00-[项目模板-XX年XX月]` 目录，替换其中的占位名称，作为本项目的资料归档目录。
4. 打开会议纪要模板，填写会议基本信息、参会人员、项目基本信息、议题结论和遗留问题。
5. 将借货、用例、版本、环境、日报、报告和复盘等过程资料归入对应目录。

示例目录：

```text
2026-08-XX-某客户项目/
├── 某客户项目_售前测试分析会议纪要.xlsx
└── 项目资料/
    ├── 1.借货设备/
    ├── 2.测试用例/
    ├── 3.测试版本MIB&软件及工具/
    ├── 4.环境及拓扑/
    ├── 5.测试工具使用方法/
    ├── 6.测试报告及复盘报告/
    ├── 7.测试日报/
    └── 8.其他/
```

## 模板填写说明

每份产品线模板均包含一张对应产品线的工作表，主要分为以下内容：

| 区域 | 填写内容 |
| --- | --- |
| 会议简介 | 会议时间、地点、召集人、纪要整理人及密级。 |
| 与会人员 | 参与部门、角色、姓名和备注信息。 |
| 项目基本信息 | 项目背景、重要性、客户立项情况、预算、招标时间、测试性质、客户关系和参与度等。 |
| 会议内容 | 各项议题、会议结论、是否存在遗留问题及补充说明。 |

建议在会议结束后及时补全结论与责任事项。对于遗留问题，应在备注中明确责任人、计划完成时间和跟踪方式，避免仅标记“有问题”而无法闭环。

## 资料归档约定

| 目录 | 建议归档内容 |
| --- | --- |
| `1.借货设备` | 借货清单、出入库记录、设备信息和归还证明。 |
| `2.测试用例` | 测试范围、测试用例、评审记录和用例变更记录。 |
| `3.测试版本MIB&软件及工具` | 测试版本、MIB、软件包、工具及其版本说明。 |
| `4.环境及拓扑` | 网络拓扑、设备清单、地址规划、配置备份和环境变更记录。 |
| `5.测试工具使用方法` | 工具安装、参数配置、操作步骤和常见问题说明。 |
| `6.测试报告及复盘报告` | 阶段报告、最终报告、问题复盘和经验总结。 |
| `7.测试日报` | 每日进展、风险、阻塞项和次日计划。 |
| `8.其他` | 与测试相关但不适合归入上述分类的资料。 |

## 维护建议

- 新增产品线时，以现有模板为基础复制并修改，保持会议简介、参会人员、项目基本信息和会议内容等核心区域的一致性。
- 更新模板时，优先在副本中完成校验后再替换原文件，避免破坏已验证的样式、数据验证或公式。
- 不要将真实客户敏感信息、账号密码、密钥、完整配置备份或未脱敏的测试数据提交到仓库。
- 对模板进行重大调整时，请在提交说明中写明适用产品线、变更原因和影响范围。

## 贡献

- 新增资料目录与现有归档约定不冲突，或已在 README 中补充说明。
